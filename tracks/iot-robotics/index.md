# IoT & Robotics

IoT connects sensor readings, controller logic and useful outputs; robotics adds controlled movement and interaction with the environment. During **12-13 November 2026**, teams build an educational campus/community prototype using allocated hardware, an approved simulation or both. An internet-connected prototype, cloud service and purchasing components are not requirements; browser-based tools may still need connectivity to load and save projects.

Beginners with basic programming/electronics knowledge can start with one input and an LED. Intermediate teams should be ready to read sensor values, choose thresholds and test alert states. Advanced teams should be comfortable with control logic, motor commands and debugging a repeatable route/obstacle sequence. Prior robotics experience is not required for every challenge; learn the tools for your selected build rather than every component listed.

## Choose one challenge

Each team selects **ONE** challenge:

| Challenge | Difficulty | Required outcome |
|---|---|---|
| Room Activity & Energy Cue | Beginner | Read PIR motion input, show activity with an LED and return to idle after the stated timeout. |
| Safer Campus Environment Monitor | Intermediate | Use MQ-2, a thermistor or both to produce normal/alert states and explain safe response guidance. |
| Rover Rescue Run | Advanced | Complete a marked route, respond to an obstacle and stop at the destination with repeatable control. |

Use Arduino Uno R3 or ESP32 where suitable, Arduino IDE or an equivalent environment, and only the selected challenge's physical or virtual components. Wokwi is recommended for circuit/controller simulation. Another approved circuit or virtual robotics simulator is acceptable if it can demonstrate the same outcomes; confirm suitability with the mentor. Wokwi alone is not a full rover-physics simulator.

The physical pool is limited, including one shared rover. Simulation is a complete participation route, not a fallback that loses marks. See [Challenges](challenges.md) for components, implementation steps and acceptance checks, [Content & Curriculum](content.md) for preparation, and [Curated Resources](resources.md) for setup references.

## Assessment and submission

Each tier is assessed directly out of **100 points**, without a difficulty multiplier or hardware-access bonus. Approximately two to three judges may inspect your code, diagram, implementation and test results, and ask you to repeat safe input scenarios. Their independent scores are averaged to rank teams. **No slides or formal pitch are required, and demonstrations carry no separate presentation marks.** The top three teams qualify for the Grand Finale; the highest-ranked team receives **Best IoT and Robotics Solution**.

The allocation is **35 functionality + 20 design/integration + 20 testing/reliability/safety + 15 code/diagrams/documentation + 10 practical relevance/SDG alignment = 100 points**. Prepare source code, a component/pin or system diagram, reproducible setup, test evidence and the common backup video. The [Track Rules](rules.md) explain safety, submissions and technical tie-breakers. Uncalibrated hardware and simulation are not certified safety measurements.
